# nim-loopback

相手が、この機械の中からしか届かないか (ループバックか) を、1 つの規則で答える。待ち受けるアドレス、Host ヘッダー、URL のホストのどれにも使う。

```nim
import nim_loopback

isLoopbackHost("127.0.0.1")              # true    アドレスか名前 (ポートなし)
isLoopbackAuthority("[::1]:8080")        # true    host[:port] — Host ヘッダー、待ち受けるアドレス
isLoopbackUrl("http://localhost:3001/")  # true    URL のホスト
isLoopbackUrl("http://127.0.0.1.evil.example/")  # false
```

困るのは、外の相手をループバックと見なす向きの誤りである (認証を省く、秘密を平文で送る)。だから、はっきりループバックと言えないものは、ループバックとしない。

## 規則

| ID | 規則 | 根拠 |
|---|---|---|
| LB-01 | IPv4 は、0〜255 の 10 進数 4 つで、最初が 127。先頭に 0 のつく数は読まない (`0177` を 8 進と読む実装がある) | RFC 1122 (127.0.0.0/8) |
| LB-02 | IPv6 は、`::1` をどの書き方でも (角かっこの有無、展開形)。IPv4 を写した `::ffff:127.0.0.0/104` も。ゾーンつき (`%lo0`) は見なさない | RFC 4291 |
| LB-03 | 名前は `localhost` だけ (大文字小文字は問わない)。`*.localhost` と末尾のドットは見なさない (DNS に流れることがある) | RFC 6761 |
| LB-04 | `host[:port]` は、ポートを切り離してから。ポートつきの IPv6 は角かっこに入る (`::1:80` は ::1 のポート 80 ではなく、アドレス ::1:80) | — |
| LB-05 | URL は、そのホスト。ユーザーの部分 (`http://127.0.0.1@evil.example/`) はホストではない | — |

`0.0.0.0` と `::` は「すべての口」であって、ループバックではない。

## 出どころ

2026-10-15 に、リポジトリごとにそれぞれの規則で書かれていた判定をまとめた。規則はそろっていなかった (`127.` で始まれば可、`127.0.0.1` だけ可、`[::1]` は可・不可、Host のポートを読まない)。`127.` で始まるかで判定すると、`127.evil.example` のような名前もループバックとみなしてしまう。

同じ日に、mcp-nim-sdk (Host、Origin、待ち受け) ほか、待ち受けのアドレス・Host・接続先の URL を判定していたリポジトリが、これを使うよう替えた。SSRF 対策のようにプライベートアドレス全般を見るものや、IP の分類そのものを扱うものは、用途が違うので替えていない。
